# 5.3. Descripción de los Módulos

## Arquitectura General

TaskUni sigue una arquitectura en capas que separa claramente la interfaz gráfica, la lógica de negocio, el almacenamiento en memoria y la persistencia en base de datos. Esto permite que cada componente sea independiente y mantenible.

Las capas principales son:
- **Presentación:** Ventanas y controles visuales con los que el usuario interactúa.
- **Servicios:** Contienen la lógica de negocio y orquestan las operaciones.
- **Estructuras de datos:** Trabajan en memoria para ordenar y gestionar tareas de forma eficiente.
- **Acceso a datos:** Se encargan de la comunicación con la base de datos.
- **Base de datos:** Almacena toda la información de forma permanente.

---

## Módulo 1: Modelos de Datos

Define las entidades fundamentales del sistema y sus propiedades.

**Tarea:** Representa una actividad académica con título, descripción, fecha límite, prioridad (Alta, Media, Baja) y estado (Pendiente, Completada, Vencida). Calcula automáticamente cuántos días restan hasta la fecha límite y asigna colores visuales según la urgencia: verde para 8 o más días, naranja para 4 a 7 días, rojo para 3 o menos días, y morado si ya venció.

**Usuario:** Representa a un estudiante con su carné universitario, nombre y contraseña.

**Acción de Historial:** Guarda una copia del estado de una tarea en el momento exacto en que se realizó una acción, permitiendo revertir cambios posteriormente.

---

## Módulo 2: Estructuras de Datos en Memoria

### Árbol AVL
Es la estructura central del sistema. Se trata de un árbol binario de búsqueda que se mantiene automáticamente balanceado, garantizando operaciones rápidas incluso con muchas tareas. Las tareas se ordenan dentro del árbol según su urgencia: las que tienen menos días restantes quedan primero, y en caso de empate se usa el ID de la tarea.

El árbol se balancea solo después de cada inserción o eliminación, utilizando rotaciones que corrigen cualquier desbalance. Esto asegura que el sistema siempre responda de forma eficiente.

### Pila de Deshacer
Es una estructura LIFO (último en entrar, primero en salir) que almacena un historial de las acciones realizadas. Cada vez que el usuario crea, edita o completa una tarea, se guarda una copia del estado anterior. Al deshacer, se recupera la última acción guardada y se restaura el sistema al punto anterior.

---

## Módulo 3: Acceso a Datos

Gestiona toda la comunicación con la base de datos MySQL.

**Conexión a base de datos:** Lee las credenciales desde un archivo de configuración externo, evitando que estén escritas directamente en el código. Los parámetros como el servidor, el nombre de la base de datos, el usuario y la contraseña se definen en un archivo separado.

**Repositorio de Usuarios:** Se encarga de la autenticación y el registro. Verifica el carné y la contraseña al iniciar sesión, y permite crear cuentas nuevas asegurándose de que el carné no esté duplicado. Las contraseñas se almacenan de forma segura aplicando un algoritmo de hash.

**Repositorio de Tareas:** Realiza todas las operaciones sobre las tareas: consultar, insertar, actualizar, completar y eliminar. Cada operación está ligada al usuario correspondiente para que cada estudiante vea únicamente sus propias tareas.

---

## Módulo 4: Servicios de Negocio

### Servicio de Tareas
Es el módulo que orquesta toda la lógica de gestión de tareas. Coordina la base de datos, el árbol AVL y la pila de deshacer para mantener todo sincronizado. Cuando se crea una tarea, la inserta en la base de datos, la agrega al árbol AVL para mantener el orden y guarda una copia en el historial de deshacer. Lo mismo ocurre al editar, completar o eliminar.

### Servicio de Reportes
Genera estadísticas y análisis sobre el rendimiento académico del estudiante. Calcula cuántas tareas hay por prioridad, por estado, por nivel de urgencia. También produce un resumen general con porcentaje de completación, identifica tareas vencidas y próximas a vencer, analiza la carga de trabajo semanal y detecta los días con mayor concentración de tareas.

### Servicio de Simulación
Permite simular el paso del tiempo para anticipar escenarios futuros. El usuario puede avanzar uno o varios días, o saltar a una fecha específica. El sistema calcula qué tareas se vencerían en esa fecha futura, cuáles estarían próximas a vencer y genera recomendaciones automáticas. También detecta cuellos de botella, es decir, fechas donde hay demasiadas tareas concentradas, y proyecta la carga de trabajo semana a semana.

## Módulo 5: Interfaz de Usuario (Ventanas)

El sistema cuenta con diez ventanas o paneles principales:

1. **Login:** Pantalla de inicio donde el usuario ingresa con su carné y contraseña, o se registra si es nuevo.

2. **Ventana Principal:** Contenedor que aloja el panel de control central.

3. **Panel de Control (Dashboard):** Es la pantalla más importante. Tiene un encabezado con el nombre del usuario, un menú lateral con todas las acciones disponibles y un panel central que muestra la tabla de tareas ordenadas por urgencia. Desde aquí se pueden crear, editar, completar y eliminar tareas, así como acceder a las demás funcionalidades.

4. **Nueva Tarea:** Ventana emergente para crear tareas con campos de título, descripción, fecha límite y prioridad.

5. **Editar Tarea:** Ventana emergente para modificar una tarea existente, con todos sus campos precargados.

6. **Simular Días:** Ventana que permite configurar la simulación temporal, ya sea avanzando una cantidad de días o yendo a una fecha específica.

7. **Resultado de Simulación:** Muestra los resultados de la simulación con tarjetas de resumen, listas de tareas vencidas y próximas, y recomendaciones.

8. **Reportes:** Ventana con pestañas que muestran recomendaciones automáticas, estadísticas detalladas, cuellos de botella y análisis de carga de trabajo.

9. **Visualización del Árbol AVL:** Dibuja gráficamente el árbol AVL con las tareas como nodos coloreados según su urgencia, mostrando las conexiones entre ellos y datos como altura y factor de balance.

10. **Cambiar Contraseña:** Permite al usuario cambiar su contraseña con un indicador visual de seguridad que evalúa la fortaleza de la nueva contraseña en tiempo real.

---

## Módulo 6: Configuración Global

Define la apariencia general de la aplicación utilizando temas de Material Design, con una combinación de colores púrpura y verde. También establece estilos personalizados para botones, menús y colores de estado que se mantienen consistentes en toda la interfaz. El punto de entrada de la aplicación es la ventana de inicio de sesión.
